# Block 58 — make the network usable by a stranger agent

Goal (owner): "the getunstuck is the social network that will be created by the agent … A social network means
agents can actually use it — post what they are stuck on, read and answer each other, mark the answer that worked,
and pay for it in Nano. A page that only describes that is not the network."

Task given to this session: **ship the social network.**

So there are two independent failures, and only one of them is the deploy:

1. **Not deployed.** The SPA exists locally and has never been promoted; production is the earlier landing page.
2. **The SPA cannot reach its own API where it is deployed.** `resolveApi` returns `window.UNSTUCK_API`
   (never set on a static build) or the same-origin `/unstuck/api` (a Caddy path that does not exist on Vercel) or
   falls back to plain `http://172.86.112.140:4310` — which an https page blocks as mixed content. So even after a
   successful deploy, an agent landing on getunstuck.space would see the shell and "Failed to load asks".

A third, smaller failure: the deployed site shipped **no** `agent.json`, `llms.txt` or `try-nano.html`, so a machine
agent visiting the domain finds nothing that tells it how to take part.

## Brainstorm (angles: make it load; make it usable; make it honest; make it cheap to keep honest)

**A. Make the page reach the API (5 ideas)**

1. **Baked same-origin API base.** Ship an `api.json` with the site that names the API base, and have
   `resolveApi` read it before falling back. *Excluded:* async, races with the first render.
2. **A build-time constant in the HTML.** `const DEFAULT_API = "https://172-86-112-140.sslip.io/unstuck/api"`.
   One line, no new file, no new request, works over TLS because the Caddy host terminates TLS with a real cert.
   The path is stable (Caddy `handle_path /unstuck/api/*`); the hostname encodes the IP, so it moves only when the
   box moves — and then the whole swarm's URLs move anyway.
3. **A `/api` rewrite in `vercel.json`.** Cleanest long-term, but Vercel's rewrite needs an origin host and the API
   is served on a bare IP:port; a rewrite to `http://172.86.112.140:4310/api/:path*` still ends in mixed content
   because the *page* is https. *Excluded* — it looks right and cannot work.
4. **Serverless proxy function.** Adds a deploy surface and a runtime that can fail independently. *Excluded* for
   now: one more thing to break between an agent and an ask.
5. **Keep the fallback order, fix the default.** `UNSTUCK_API` override → same-origin `/unstuck/api` → **default
   constant**, with the constant corrected to the TLS base. This is idea 2 expressed as a rule, not a special case.

Chosen: **5 (which is 2 done properly).**

**B. Make it usable (5 ideas)**

6. **Show the ask list without any API.** *Excluded:* the asks change; a static copy is a lie within a minute.
7. **Ship the discovery files.** `agent.json`, `llms.txt`, `try-nano.html` already exist in the working copy and
   were never sent. Shipping them costs nothing and gives a machine agent the on-ramp, the endpoints and the
   Nano-only rule in one fetch. **Kept.**
8. **Make the empty state instructive.** A fresh agent that lands on an empty list must be told what to do. The
   current empty state says "No asks yet. Be the first" — kept and made explicit about the 0.00001 XNO opener.
9. **Add a "welcome" broadcast per agent.** *Excluded:* a wall of broadcasts is what Block 41 spent effort burying;
   the list already defaults to genuine asks.
10. **Require no wallet to read.** Already true — kept as a property, tested.

**C. Make it honest (4 ideas)**

11. **The site stops publishing numbers a human typed.** `ledger.json` is generated by `publish.js`; the page must
    read it and never hard-code. **Kept as a law.**
12. **Say the denominator next to the number.** Already on the About tab; the law makes it observable.
13. **A funnel the owner can read at a glance.** Not part of the site; goes in the journal. *Deferred.*
14. **Count only unsubsidised transactions.** Already the rule; keep the stat and let it read 0.

## The invention

**One change, in the working copy, that makes getunstuck.space the network rather than a page about one:**
the SPA resolves its API to a **TLS-reachable same-origin-by-proxy base** by default, the three machine-readable
entry points ship with it, the empty states tell an arriving agent exactly what to do, and every number on the page
is read from the generated `ledger.json` — then the whole thing is deployed through `rai-web`.

## Laws minted (see .ledger via `bin/ledger list`)

- **L31** — the shipped page resolves its API to a base an https page can actually call.
- **L32** — the shipped site is the SPA *and* the machine-readable entry points, all reachable at the domain.
- **L33** — a stranger agent can read the network, and the page says what to do when it is empty.
- **L34** — every number the page prints comes from the generated ledger, never from the markup.
