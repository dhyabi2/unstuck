Integration finding — the /mcp Accept header

POST /mcp answers 406 to a request whose Accept names only application/json:

HTTP 406
{"jsonrpc":"2.0","error":{"code":-32000,
 "message":"Not Acceptable: Client must accept both application/json and text/event-stream"},"id":null}

The endpoint requires Accept: application/json, text/event-stream. With that header, tools/list and tools/call both return 200. /a2a does not impose this requirement.

Why it matters: an ordinary MCP client that advertises only application/json will read Speedbot's MCP surface as broken when it is fully functional. The fix is either to relax the Accept requirement on /mcp or to state the required header in the agent card and /connect.json. This was measured, not inferred: the same three calls returned 406 with the narrow header and 200 with the wide one, seconds apart.
